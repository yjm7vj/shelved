› Phase 1 — Project setup + auth + database Weeks 1–3
1
Learn Next.js 14 basics
Work through the official Next.js tutorial on nextjs.org. Focus on App Router, pages, and components. Skip the advanced stuff for now.
learn
2
Learn TypeScript fundamentals
Types, interfaces, and how they layer onto JavaScript. The Total TypeScript free beginner course is great. 2–3 hours is enough to start.
learn
3
Scaffold the Next.js project
Run npx create-next-app@latest gameboxd --typescript --tailwind. Push to a GitHub repo immediately. This is your home base.
build
4
Set up Supabase project
Create a free Supabase project at supabase.com. This gives you a managed PostgreSQL database. Copy your connection string into a .env file.
build
5
Design and create your DB schema
Create tables: users, games, user_games (hours + status), reviews, friendships. Use Supabase's table editor visually first, then write the SQL. This is the most important step — get it right before moving on.
build
6
Add auth with Clerk
Install Clerk, add email + Google login. Protect routes so only logged-in users can add games or write reviews. Connect Clerk user IDs to your users table in Supabase.
build
7
Build basic game search page
Hit the RAWG API to search games by name. Show cover art and title in a grid. This is your first real UI — make it look good with Tailwind + shadcn/ui components.
build
› Phase 2 — Steam integration + background jobs Weeks 4–8
8
Learn Python + FastAPI basics
Work through the FastAPI official tutorial (fastapi.tiangolo.com). Focus on routes, request/response models with Pydantic, and async functions. Give this a solid week.
learn
9
Get a Steam Web API key
Register at steamcommunity.com/dev/apikey. Free and instant. Read the GetOwnedGames and GetPlayerSummaries docs so you know exactly what data you'll get back.
build
10
Build the FastAPI backend
Create a new repo for your Python backend. One endpoint to start: POST /sync-steam that accepts a Steam ID, calls the Steam API, and returns the game list. Test it with a public Steam profile.
build
11
Set up Upstash Redis + job queue
Create a free Upstash Redis instance. Use the rq or arq Python library to turn Steam syncing into a background job. Your API should return immediately and process async.
build
12
Build the Steam import UI
A page where users paste their Steam profile URL or ID. Show a loading state while the job runs, then redirect to their library page when done. Use Supabase realtime to detect when the sync finishes.
build
13
Build the game library page
Display the user's imported games with hours played, cover art from RAWG, and a status badge (playing / completed / backlog). This is your hero feature — make it look great.
build
› Phase 3 — Reviews, ratings + social Weeks 9–13
14
Build game detail pages
Each game gets its own page: cover art, description from RAWG/IGDB, average rating, and a list of reviews from users. Use Next.js dynamic routes ([gameId]/page.tsx).
build
15
Add reviews and star ratings
Users can write a review and give 1–5 stars. Store in your reviews table. Show average rating on the game page. Add a "did you play this?" check using their imported Steam library.
build
16
Build user profile pages
Public profile showing: avatar, bio, games played, recent reviews, stats (total hours, games completed). This is what people share. Make it look clean — this is your showpiece.
build
17
Add the friend / follow system
Users can follow each other. Store in a friendships table with follower_id and following_id. Show a follower count on profiles.
build
18
Build the activity feed
Show recent activity from people you follow: "Alex completed Elden Ring", "Sam wrote a review for Hades". Query reviews + user_games ordered by created_at for followed users.
build
› Phase 4 — AI recommendations Weeks 14–17
19
Learn embeddings + vector search
Read the OpenAI embeddings guide and the pgvector README. The core idea: turn text into a list of numbers, then find similar ones. One afternoon of reading is enough to proceed.
learn
20
Enable pgvector on Supabase
Run create extension vector in your Supabase SQL editor. Add a vector(1536) column to your games table. Supabase has a pgvector quickstart guide — follow it exactly.
build
21
Generate and store game embeddings
Write a Python script that takes each game's name + genres + description, calls OpenAI's text-embedding-3-small API, and stores the vector in your games table. Run it once for your game catalog.
build
22
Build the recommendation endpoint
In FastAPI: take a user's top played games, average their embeddings, run a pgvector nearest-neighbor search, filter out games they already own, return the top 10. That's the whole algorithm.
build
23
Add "recommended for you" UI
A section on the user's home feed showing AI-recommended games with a "because you played X" explanation. Pull the reason from whichever owned game had the closest embedding match.
build
› Phase 5 — Deploy + cloud + polish Weeks 18–20
24
Deploy frontend to Vercel
Connect your GitHub repo to Vercel. It auto-detects Next.js. Add your environment variables (Supabase URL, Clerk keys, etc.) in the Vercel dashboard. Your first cloud deployment — takes about 10 minutes.
deploy
25
Deploy backend to Railway
Connect your FastAPI repo to Railway. Add a Procfile with your start command. Add environment variables. Railway detects Python automatically. Set up a worker process for your Redis job queue.
deploy
26
Set up GitHub Actions CI/CD
Add a workflow that runs your tests on every push and auto-deploys to Vercel/Railway on merge to main. Even a basic pipeline here is worth listing on your resume as CI/CD experience.
deploy
27
Add monitoring with Sentry
Free tier Sentry catches runtime errors in both your Next.js frontend and FastAPI backend. Add it in an hour. Now you can see real errors from real users — this is what production observability looks like.
deploy
28
Get real users + collect metrics
Share in gaming communities, with friends, on Reddit (r/patientgamers, r/SteamDeals). Get 20–50 real users. Note your numbers: active users, Steam profiles imported, reviews written. These go on your resume.
deploy
29
Write a project README + case study
Document architecture decisions, what broke, what you'd do differently. This is what interviewers read. Explain why you used a job queue, why pgvector, why you split frontend and backend.
deploy
